# 逐人联系后精筛

## 新流程

推荐页逐人读取 → Flash 粗筛（临界/异常由 Plus 复核） → 粗筛通过即准备首条消息 → 打招呼 → 发送首条消息 → 获取联系后在线简历 → Plus 精筛 → 下一人。

- 不再等全部候选人精筛完后按分数统一联系。
- AI 消息依据当前候选人的粗筛可见资料生成，并在发送前独立复核；不依赖尚未取得的完整简历。
- 一人有完整简历时先完成精筛再处理下一人；暂未取得则保存 `waiting_resume` 后处理下一人。稍后恢复任务补做精筛，无需其仍出现在推荐列表中。
- 名额按打招呼尝试计数；精筛不通过不会退回名额。页面分别显示已确认打招呼、已使用名额、等待简历、精筛通过数。
- 发送前持久化状态；不明发送结果保留待核查，不自动重发。已确认打招呼但尚未发送首条消息，可恢复该步骤；已完成联系而精筛 API 失败，可只恢复精筛。
- 名单仍位于 `recruitment_app/.runtime/results/<职位名称>_<日期>/qualified_contacted.txt`，每人间隔一行，只收录已完成首条消息且精筛通过者。
- 暂停在最后一次精筛调用期间也不会被错误覆盖成 finished。

## 联系后简历读取

使用当前登录账号的会话列表与会话详情绑定候选人、关联职位及 securityId，再读取在线简历。支持实际接口的 uid/encryptUid 会话字段及 geekProjExpList 项目字段；身份不一致、关联职位缺失、隐藏资料或章节缺失时不伪装成完整简历。

对一个既有会话进行了只读验证，取得 16951 字在线简历。未为测试打招呼、发送首条消息或调用评分 LLM；该验证不代表所有候选人联系后都能立即取得完整资料。

## 代码范围

- `runner.py`：逐人状态流程、配额、等待恢复及导出条件。
- `boss.py`：懒加载逐人摘要、联系后简历、会话字段兼容。
- `web.py` / `app.js` / `index.html`：等待状态、恢复入口、联系计数和文案。
- 测试覆盖顺序、配额、等待、拒绝导出、API 失败恢复、暂停恢复、发送不重试及身份绑定。

重启网页服务后生效：`.\recruitment_app\run.ps1`。
