# 筛选模型切换：Flash + Plus

## 已实施

- 粗筛：`qwen-flash`，非思考模式。
- 精筛、岗位评分标准提取：`qwen-plus`，非思考模式。
- 粗筛遇到校验问题、无有效分数或阈值附近 ±5 分时，使用 Plus 复核。
- 模型全部通过阿里云 API 调用，不在本地运行模型。
- 生产网页默认模型工厂已切换；现有服务需要重启才会载入新代码。
- 原评分公式、提示词、标签、数据划分不重做；此前 Plus 精筛和岗位标准缓存继续复用。
- 新评测版本为 `evidence-v3-hybrid-reviewed2`，复核区间固定 45–55（基准粗筛阈值 50）。
- 本次固定已有 BASE 权重、覆盖率与阈值，不再做参数网格搜索。
- Flash 返回完整但扁平的 JSON 时，仅补齐包装层，不补充或推测证据；仍经过原文引用与评分校验。

## 缓存与评测边界

- Flash 粗筛、格式适配、复核组合均有独立缓存；Plus 精筛沿用原 v3 缓存。
- 格式适配仅单向读取复用已验证的旧 Flash 输出，不将新结果写回旧缓存。
- 初次 `hybrid` / `format1` 试运行已中断，只用于发现格式兼容问题；不作为独立版本的性能比较数据。
- 开发集先抽取 60 份简历、300 个岗位配对。600 个阶段结果包含已有缓存，不能视为 600 次新增 API 调用。
- 网页本地评测的证据提取和修复已按实际阶段模型生成缓存键；该旧评测入口不代表新版通用评分最终测试。
- 最终留出测试尚未开启，不能宣称分类效果达标。

## 本次验证

- 两个模型均成功返回 API 探测结果，原账户欠费阻断已解除。
- 84 项评分、缓存、路由、本地评测、接口与消息测试联合通过；之后新增的两项缓存隔离/失败保留测试也通过（混合路由专项共 10 项通过）。
- 代码审查发现的缓存反向写入、网页本地评测绕过路由、格式异常未复核、离线参数策略不一致、组合失败记录缺失问题均已修复。

## 开发集结果：未达标

60 份简历、300 个岗位配对，600 个阶段结果已完整缓存，技术校验失败为 0；不是最终留出测试。

| 指标 | 结果 |
|---|---:|
| 粗筛召回率（标签 1/2 为正） | 27.40%（40/146） |
| 粗筛精确率 | 85.11%（40/47） |
| 两层通过的召回率（标签 2 为正） | 2.70%（2/74） |
| 两层通过的精确率 | 100%（仅通过 2 对，不能证明稳定） |
| 三分类准确率 | 54.00% |
| Plus 粗筛复核 | 190/300（63.33%） |

106 个粗筛假负例中，104 个证据覆盖率不足 40%，105 个不满足进入通过判定的条件，102 个分数不足 50 或无有效分数；原因互有重叠。

只使用已有缓存、在相同 262 对上的对照：
- 原 Plus 粗筛召回率 18.80%，组合为 23.93%。
- 原 Plus 粗筛精确率 81.48%，组合为 82.35%。
- 该子集由缓存可用性决定，有选择偏差，不能作为正式模型优劣结论。

结论：本次模型切换已完成，但原规则/证据覆盖/银标签之间的差异仍未解决。不能把低召回完全归因于 Flash，也不能因单价下降就宣称实际费用显著下降；复核率偏高会抵消节省。

为避免重复花费，本轮未扩大全量 API 评测、未打开最终留出集、未改默认评分规则。下一步应针对这些失败样本核对岗位要求、短简历证据和标签，再决定是否需要局部修改；不重建已完成的翻译、标签及全部提示词。
