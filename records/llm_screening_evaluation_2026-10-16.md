# 粗筛与精筛本地评测记录

日期：2026-10-16。测试岗位：本体建模实施与交付工程师（伙伴）。

## 模型与实现

- 仅调用阿里云 `qwen-plus` API，非思考模式、temperature=0；没有下载或运行本地模型。原选定快照 `qwen-plus-2025-07-28` 返回404，当前别名调用成功。
- LLM逐项给出证据强度level、任务相关性fit（各0—4）、原文行号、硬条件判断及简短理由。程序还原引用、校验证据，无效时最多纠正一次；仍无效则待复核。
- 原始分为 `Σ(weight × level × fit / 16)`；仅技能罗列的证据强度最多1。学历相关专业只可由已核验教育原文修正。
- 粗筛允许局部卡片中的核心或技能证据进入精筛；精筛要求更完整的能力组合。正式流程与评测共用评分函数，网页展示分数、理由、规则调整和缺口。
- 早期借鉴Recruiter Pro的技能匹配组件；本轮能力门槛和分档规则为当前项目新增，不是直接复用该项目的评分结果。

## 本体实施岗位的精筛规则

从岗位标准识别四个独立能力项，最低要求如下。无法明确识别该组合时使用通用评分。

| 能力 | 最低level | 最低fit |
| --- | ---: | ---: |
| 对象、属性、关系等建模 | 2 | 2 |
| SQL | 2 | 3 |
| Python或JavaScript | 1 | 2 |
| 软件实施、数据接入或项目交付 | 3 | 3 |

最终分档（raw为原始分）：

| 档位 | 条件概要 | 最终分 |
| --- | --- | --- |
| 合格 | 四项能力及硬条件均通过 | 75 + 0.25 × raw |
| 潜力 | SQL与编程达到门槛，其余有缺口，硬条件无明确失败 | 50 + 0.24 × raw |
| 相关但有缺口 | 有可确认的相邻技术领域经历 | 20 + 0.29 × raw |
| 无关 | 无上述技术关联 | 0.19 × raw |

分数表达岗位匹配层级，不是录用成功概率。降低阈值也不能绕过精筛能力门槛；硬条件未知时保留复核。技术词的否定语境不作为正向关联。

## 数据与结果

共120份：100份来源合成简历、8份本地PDF、10份外部无关职业负例、2份市场/体育压力样本。沿用既有复核标签，本轮未修改标签迎合得分；标签不传给LLM。

细分类组成：高匹配3、边界43、困难负例23、普通负例33、无关12、私人拒绝样本6。粗筛采用从正文提取的最多200字代理卡片，并非真实BOSS卡片。

阈值：**粗筛2、精筛75**。“载入测试岗位”会同时设置这两个值；通用页面初始粗筛阈值仍为30，不将本次阈值推广至所有岗位。

| 指标 | 最终结果 |
| --- | --- |
| 端到端是否放行（粗筛通过且精筛通过） | 120/120，TP=3、TN=117、FP=0、FN=0 |
| 端到端精确度 / 召回率 | 100% / 100% |
| 粗筛召回率 / 精确度 | 95.7% / 88.0% |
| 粗筛0.75×召回率+0.25×精确度 | 93.7% |
| 粗筛标签一致 | 102/114；6份私人拒绝样本无粗筛标签 |
| 精筛通过/复核/拒绝三分类一致 | 79/120；仍有41份细分类分歧 |
| 精筛理由覆盖 | 120/120，无错误记录 |

初始完整基线的粗筛、精筛正例召回均为0；排查并修正证据行引用、短卡片技能截断、相关专业识别及能力门槛后得到上述结果。最终报告保留各阶段指标与分歧样本，不能把二分类全对解释为所有细分类标签全对。

| 样本层级 | 精筛分数范围 |
| --- | ---: |
| 高匹配 | 83.1—95.7 |
| 困难负例 | 20.7—56.7 |
| 无关领域 | 0—0.7 |

市场样本0.4、体育样本0.7。高匹配最低分与困难负例最高分相差26.4；困难负例最低分与无关最高分相差20.0。高匹配A001、A002、S022均通过两层筛选。

按粗筛排序，前10份有2份高匹配（20%），前20份有3份（15%）。这是本地排序代理指标，不能保证线上每天实际接触简历中的高匹配比例。

## 结果边界

同一批样本参与了调优和验收，只有3个高匹配正例，且大量样本为合成数据；没有独立留出集。因此已经实现本地最终放行判断全部区分，但尚不能声称未知简历准确率100%，也没有实现所有边界/困难负例细分类完全一致。上线后的真实卡片覆盖率、候选人分布与每日10%目标需另行验证。
