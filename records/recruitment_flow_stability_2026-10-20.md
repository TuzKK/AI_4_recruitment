# 招聘流程稳定性修复与验证

## 修复范围

1. 去除粗筛详情读取、打招呼前绕行沟通页的刷新，避免推荐名单变化导致目标丢失。
2. 详情读取前后关闭简历弹窗，并检查弹窗确实消失；不能确认关闭时停止本轮。
3. Chrome 后台窗口曾使简历进入/离开动画停滞。页面操作前激活绑定的 BOSS 标签页并恢复最小化窗口。
4. 粗筛摘要只采用本次打开后、候选人 ID 匹配的最新观察消息，有限等待异步加载。避免历史重复消息让同一候选人被误判为身份歧义。
5. 支持推荐列表滚动加载。修正 BODY 与实际 document.scrollingElement 不一致造成的无效滚动。
6. 每轮按候选人 ID 去重；连续三轮无加载进展才停止，单次最多扫描 200 个新候选人。达到上限暂停，可在同一任务恢复；加载历史已处理候选人也算翻页进展。
7. 发送前目标已消失时标为 candidate_unavailable，不占用名额并继续下一人。其他明确发送前失败与发送结果不明分别处理。
8. 消息回执不再使用 received 判断收发方向：实测已发送消息该字段也为 true。改为绑定账号发送者、接收者 UID、准确正文三者核验。
9. 发送响应异常时只重读聊天记录，不重复发送。保留原始发送错误。
10. UI 展示结束原因；精筛尚为空时仍显示粗筛理由。
11. 禁止 Windows 同端口重复启动网页服务；只有绑定端口成功才恢复任务状态，避免第二个进程改写第一个进程中的任务。

扩展版本：0.2.23。没有修改招聘评分权重或阈值。

## 验证结果

- 完整 Python 回归：108 项通过，92.12 秒。
- 后续增加“恢复时跨越历史已处理页面”的回归，相关 26 项通过。与完整回归有重叠，不累计为 134 项。
- 浏览器 JS 测试：42 项通过；app.js 语法检查、所改核心文件 diff 空白检查通过。
- 独立代码审查发现并修复弹窗残留、扫描上限恢复、历史页面被误判为无进展的问题。
- 真实页面两轮连续详情检查：第一轮 3 人均可关闭并保持目标唯一，其中 2 人摘要匹配；摘要时序修复后第二轮 3 人全部匹配，分别读取 2175、1597、1419 字。
- 真实滚动：推荐列表有效卡片从 14 增至 28，随后增至 54。
- 按用户授权随机选择一位历史联系人，只发送一次测试消息：“您好，这是一条招聘沟通功能测试消息，无需回复，打扰了。”
- 该消息已在历史记录按发送者账号、收件人 UID 和正文确认；未重发。原 received 逻辑曾误报未确认，现已修复。
- 该历史联系人完整在线简历读取成功，13106 字。
- 真实阿里云 API：当前本体岗位粗筛样例经 Plus 复核得 24 分/hold；历史联系人完整简历精筛 22.5 分/not_fit；均返回理由。这是链路测试，不是准确率评测。
- 已在无活动任务时重启本地招聘网页服务；首页、app.js、active-run 接口均返回 HTTP 200。

## 实测边界

- 真实发送验证对象是历史联系人，验证了沟通消息发送与回执。未额外向陌生候选人点击首次打招呼；首次打招呼由自动化测试覆盖。
- 完整简历依赖 BOSS 实际可提供的数据；未获得完整资料仍进入等待简历状态。
- 真正发送结果不明的历史记录不会自动清除或重发。
- 页面控件变化、登录验证、平台限制仍可能中断运行；此时应显示具体原因，不能宣称所有外部情况均不会失败。
