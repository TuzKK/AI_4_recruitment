# BOSS 请求限速（扩展 0.2.26）

## 已实现

- 默认程序主动请求/页面操作间隔 5 秒，首次打招呼间隔 20 秒；界面允许分别调慢至 30 秒、60 秒。
- 包括隐式账号核验、业务 API、加载更多、打开详情和附件读取；扩展中统一串行调度，时间戳和设置保存在 Chrome 本地，跨任务及扩展重载生效。
- 已观察到 HTTP 429 或业务码 9 时进入共享冷却，至少 120 秒，遵循更长的 Retry-After。连续响应保留最长冷却期限，不自动重试写操作。
- 页面 XHR/fetch 的限流响应通过被动监听传入冷却器，仅保存限流元数据，不保存响应中的候选人信息。
- 等待时向本地服务发送心跳，网页显示等待/冷却倒计时。连接器命令期限 120 秒，客户端等待 130 秒。
- 未派发的打招呼不占用名额；已经开始发送但结果不明的记录继续保留待核查状态，防止重复联系。

## 范围说明

限速约束本程序发起的 API 请求和页面操作。BOSS 页面一次操作内部可能产生多个网络请求，网站自身的后台请求也不能逐个保证 5 秒间隔；不代表对浏览器所有网络包进行节流。

## 使用

打开 http://127.0.0.1:8765/，在 Chrome 扩展管理页重载连接器 0.2.26 后重新连接。普通限速等待会自动继续；触发平台限流时任务暂停，冷却结束后再手动恢复。结果待核查的发送记录仍需核查，不能靠恢复任务重复发送。
