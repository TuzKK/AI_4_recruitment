# 项目、改造与实测证据完整上下文

整理日期：2026-10-12。本文结合当前对话、工作区源码和已有报告；不是其他所有对话的完整导出，也不是对当前线上状态重新验收。历史记录多数来自 2026-09-29 的验证批次。

## 1. 用户目标与约束

目标是将现有开源能力封装为 Functions/Tools，构建可配置 nodes/branch/condition 的招聘 Workflow：推荐初筛、自动联系、详细简历精筛、按聊天上下文发送自定义消息，最后交由人工处理。用户强调有限打招呼额度意味着联系前筛选必须更准确；优先扩大可获取信息的范围与完整度，再研究模型与 Prompt。

正常运行必须后台自动完成，不要求人工打开“推荐牛人”、选择候选人或切换“沟通”。曾要求人工安装、更新、连接扩展，这是开发部署过程，不是可接受的日常业务步骤。独立浏览器与 OCR 目前只是后续方案。

## 3. BOSS-cli 改造分层

### 登录态与桥接

`boss_cli/browser_bridge.py` 使用绑定本机地址的 HTTP 服务；扩展通过轮询领取有限操作。请求带本地令牌，使用接口白名单及只读默认设置。`browser_session.py` 提供 CLI 侧通道选择、页面发现、目标绑定和错误处理。扩展在页面上下文中使用浏览器会话，不把 BOSS Cookie 导出给模型。

扩展包含 worker、page operation、protocol 校验及 popup 连接界面。每次操作检查目标文档及稳定账号标识，减少刷新、切换账号后的错对象操作。命令有截止时间；超时或未知发送结果不自动重放。扩展更新后的客户端身份变化曾造成连接失败，需要重启本机桥接并重新连接；重连体验仍可优化。

CLI 增加 browser transport、状态查询、页面发现、自动导航、读取卡片、按卡片 ID 打开详情和详情快照。Windows Cookie 路径兼容也有调整。启动入口为 `boss.ps1` 和 `start-browser-bridge.ps1`，连接教程见 source_snapshots。

### 读取与导出

`recruiter inbox --page` 增加显式列表分页，保留 relations 等上下文；`recruiter chat --before` 增加历史游标。验证脚本循环直到 `hasMore=false`；不要将其误写为默认命令已自动读取全部页。

原在线简历导出使用了不匹配的字段：项目实际为 `geekProjExpList`，原实现读取 `geekProjectExpList`；工作正文实际包含 `responsibility/workPerformance`，项目正文实际包含 `projectDescription/performance`。已新增字段保留型导出，避免只输出标题或漏正文；同时处理数字学历、默认文件名冲突、多岗位选择问题。字段保留型 Markdown 有大量元数据，因此另生成面向阅读的清理版本。

`.runtime/fetch_resume_batch.py` 和 `.runtime/clean_resume_batch.py` 是本地批量样本脚本，不是已交付的通用 API。清理省略空模块、接口状态、ID 等元数据，保留介绍、经历、技能、荣誉和证书；正文不做 LLM 摘要。对未知模块的覆盖仍需进一步设计，不能称为所有简历类型的无损通用清理器。

## 4. 实测证据与限制

### 推荐

历史两次读取分别取得 37 张和 15 张卡片。CLI 自动导航及按 ID 打开详情成功。后者快照总正文 8,426 字符，混有推荐列表，不能算简历全文；独立简历相关容器约 302 字符，经历概览约 285 字符。`c-resume` 嵌入页面正文为空，延迟复查一致，未捕获当前方法指定的简历接口请求。根因未确定，不能直接归因于加密、权限或画布。

曾选择未在已获取沟通列表中匹配到的推荐 ID，用已有职位参数直接调用简历接口，返回“未知的非法参数”。这只证明该参数组合失败，不证明候选人绝对未沟通过，也不证明推荐完整简历不可读取。推荐列表与已有会话存在交集，其中已有联系人简历读取成功不能作为“未联系推荐简历读取成功”的证据。

### 沟通简历

主样本返回 `friend=true`、`hiddenResume=0`，有 2 段工作、3 段项目、1 段教育及专业技能等内容。字段保留型 Markdown 约 18,707～18,708 字符，不是正文规模。

用户随后粘贴同一候选人的网页正文，我们检查本地 JSON 与既有 Markdown：个人介绍 393 字符，工作正文 467/222 字符，项目正文 327/292/503 字符，共 2,204 字符，未发现这些段落缺失。可读版约 2,946 字符，还包含接口返回的其他简历模块。该结论仅覆盖用户提供的页面内容，不代表网页所有隐藏模块都已逐项核验。

又读取 5 位已有沟通候选人，均返回 `hiddenResume=0`。五份可读 Markdown 长度为 4,802、2,016、2,843、4,456、1,886 字符；正文检查分别 10、5、9、9、9 项，共 42 项通过。该检查是原始接口到清理结果的一致性，不是五份全部与网页人工对照。具体文件见 `source/boss-cli-main/.runtime/clean-resumes-20260929/README.md`。

### 聊天与发送

聊天主样本返回 2 条消息，其中简历卡片不等于 PDF。另一会话用游标读到接口末尾，先前两页 4 条、无重复；复查每次 count=2 时共 3 次请求得到 4 条，最终 `hasMore=false`。请求次数不同不代表新增消息。

用户授权一次礼貌发送测试。原 CLI 请求 `/wapi/zpchat/fastReply/sendReplyMsg`，参数 `gid/content`，返回“缺少必要参数”。随后核对消息未增加、目标正文未出现。没有猜参数重试，服务恢复只读。确切缺失参数未知，不能断言补一个 securityId 或先调用 sessionEnter 就会修好。

打招呼是另一条路径：第一个项目有 `/wapi/zpjob/chat/start`，本地未完成实际发送验收。CLI 原版 greet 只是调用查看资料接口，不会发起真实联系。
