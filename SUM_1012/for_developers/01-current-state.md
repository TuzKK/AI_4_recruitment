# 当前做了什么

截至 2026-10-12 的整理结论：目前是“源码研究 + 改造后的采集 CLI + 样本验证”，不是已经跑通的招聘 Agent。实际业务自动化不应要求人工切换推荐或沟通页面。

## 三个项目的分工

| 项目 | 本次工作 | 定位 |
|---|---|---|
| `yaoyouzhong/boss-resume-filter` | 分析推荐采集、规则评分、Prompt、打招呼与二次评估；本次未改其业务代码 | 流程与评分参考 |
| `jackwener/boss-cli`，本地 `source/boss-cli-main` | 本次主要改造对象，并进行了线上读取验证 | 后续 Functions/Tools 的采集基础 |
| 本地 `source/Boss-main` | 局部参考浏览器连接和平台结构；本次未改造 | 已有平台候选，尚未决定集成 |

`Boss-main` 其他会话中的历史改动不计入本次成果；其上游归属未在本次审计中确认。不能把 README 声称的能力直接当作已验收功能。

## BOSS-cli 的实际改造

- Chrome 扩展 + 带令牌的本机桥接：使用现有浏览器登录态，新增 browser transport，保留 cookie 通道。
- CLI 自动导航到推荐／沟通，按候选人 ID 打开推荐详情，采集卡片和详情快照。
- 增加沟通列表页码、聊天历史游标；以脚本自动循环到 `hasMore=false`。
- 修复在线简历导出的字段遗漏：实际项目字段为 `geekProjExpList`，工作正文有 `responsibility/workPerformance`，项目正文有 `projectDescription/performance`。
- 导出保留接口字段和长正文，改进学历类型处理、岗位选择和文件覆盖保护。
- 增加账号与页面身份校验、接口白名单、默认只读及未知发送结果不自动重试。
- 本地批量抓取及清理脚本生成可读 Markdown；尚未产品化为正式批量 CLI 子命令。

## 能力边界

| 能力 | 结论 |
|---|---|
| 推荐卡片与详情入口自动操作 | 已实测 |
| 推荐完整在线简历 | 未读通；仅取得卡片与概览，不代表平台绝对无法读取 |
| 已有沟通对象详细在线简历 | 多份样本成功；其中一份已与用户粘贴的页面正文对照 |
| 聊天历史分页 | 到接口末尾的读取已通过；不包括被删除或平台不返回的消息 |
| 自动打招呼 | 第一个项目有源码实现；本地端到端发送未验收 |
| 普通聊天消息发送 | 原版接口实测报“缺少必要参数”，未发送成功 |
| PDF 附件下载 | 未验证；在线简历或简历卡片不等于 PDF |
| OCR、独立后台浏览器 | 已讨论方案，未实现 |
| LLM 优化与完整 Workflow | 未实施 |

原版 CLI 的 `recruiter greet` 只读取资料，不能按名称认定它会发送招呼。第一个项目的 `/wapi/zpjob/chat/start` 与 CLI 普通消息 `/wapi/zpchat/fastReply/sendReplyMsg` 是不同操作，后者失败不能推导前者失败。

## 样本与测试

- 简历新增抓取 5 份并清理，42 个非空正文核对项保留；这是原始返回到 Markdown 的一致性，不是 5 份均与网页逐项对照。
- 主样本原导出约 1.87 万字符，包含大量元数据；个人介绍及五段工作／项目正文合计 2,204 字符，可读版约 2,946 字符。不能以文件长度证明完整性。
- 历史测试：121 项 Python、8 项 Node 通过，7 项 smoke 未运行。本次整理未重跑测试。
