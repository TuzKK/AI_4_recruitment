# Quick Start：当前流程与优化点

当前主要改造 **BOSS-cli**；参考 **boss-resume-filter** 的采集、打招呼和评分逻辑。完整招聘 Workflow 尚未贯通。

## 当前步骤

```text
推荐牛人 → 卡片粗筛 → 自动打招呼 → 关联沟通会话
         → 读取详细在线简历 → 清理为 Markdown → 简历精筛
         → 读取聊天记录 → 发送自定义消息 → 人工接管
```

以上是目标串联顺序，各环节状态如下：

| 步骤 | 当前状态 |
|---|---|
| 推荐采集 | CLI 可自动进入推荐、读取卡片并打开详情；推荐完整简历尚未读通 |
| 卡片粗筛 | 参考项目已有规则分 + LLM ±15 分；尚未与本地 CLI 完整集成 |
| 自动打招呼 | 参考项目有 API 实现，本地尚未验收；原版 CLI `greet` 只读取资料 |
| 关联沟通 | 已有会话可读取；新打招呼后会话出现、简历可读的连续过程待验证 |
| 简历读取与清理 | 多份已有联系人的详细简历已读取并清理为 Markdown，正文核对通过 |
| 简历精筛 | 参考项目有二次评分，但受 ±15 分调整和 6,000 字符截断限制；尚未集成 |
| 聊天与后续联系 | 历史记录可自动分页读到接口末尾；普通消息发送实测缺少参数，尚未修好 |

**注意：推荐全文未读通，不等于平台必须先打招呼才允许读取。已有联系人读取成功，也不保证新联系人立即可读。**

## 优先优化点

1. **先增强联系前采集**：API 优先、DOM 补充、OCR 兜底，取得更多经历和技能证据，减少有限打招呼额度的浪费。
2. **保证后台自动与内容完整**：自动导航、展开、滚动和截图；记录字段来源与缺失，核对清理前后正文。独立后台浏览器和 OCR 尚未实现。
3. **再研究匹配模型与评分**：先调研开源简历—岗位匹配模型，再优化模型／Prompt；粗筛判断联系价值，精筛独立判断岗位适配，取消静默截断。
4. **补齐联系闭环**：验证真实打招呼和消息发送，增加预算、ID 去重、会话等待、结果核实和人工接管；未知发送结果不自动重发。

正常业务操作全部由 CLI 调度；登录失效或验证码需暂停并恢复，不能承诺永久无需人工介入。
