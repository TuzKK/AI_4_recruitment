## 结论

LLM 不直接决定总分：先过确定性条件检查，再计算规则分，最后可选 LLM 调整。BOSS 自带的 AI 评分不参与此流程。

- 规则分 `min(100, 25 + 技能分 + 超额经验分 + 学历分 + 优先项分)`。技能分为 `int(命中关键词权重 / 所有关键词权重 * 50)`；无关键词或权重总和不大于 0 时直接给 50。经验分为 `min((整年经验 - 最低年限)*3,15)`，仅设置正的最低经验时启用。学历分博士10、985/211硕士9、普通硕士7、985/211本科6、普通本科3；学历不限时学历分0。优先项按命中奖励相加，上限10。来源：`filtering.py:419-550,690-769`，`constants.py:4-20`。
- 普通初评 `final=max(0,min(100,rule_score+adjustment))`；LLM调整无论输出什么都被解析器限制到 -15~+15。四维1~10只保存用于展示，不参与总分合成。来源：`llm_eval.py:542-589,1045-1103`。
- 55以下淘汰，55~64待定，65~74推荐，75以上强烈推荐。硬条件淘汰独立于分数；已被规则淘汰的人不会被AI加分救回。来源：`constants.py:18-20`，`llm_eval.py:885-896,1051-1068`。
- 二次简历评估是替换初评调整，而不是叠加：`final=clamp(rule_score+resume_adjustment,0,100)`。已淘汰记录只存AI意见，不改分或推荐。一次硬条件结论保留。来源：`llm_eval.py:1201-1256`。

## Prompt 与调用

- 初评 system 在 `llm_eval.py:141-162`，user模板在164-169：岗位要求、格式化硬条件、候选人摘要；输出 adjustment、hard_condition_verdict、证据列表、四维分、reason。
- 二次评估 system 在174-192，user在194-200：岗位要求、硬条件、初评规则分/调整/理由、简历文本。system称完整简历，但实际代码先截至6000字符，并非保证完整传输（1160-1198）。
- 用户需求取 `rule.original_requirement`，为空时拼岗位名称/经验/学历。只有ai_eval开关、配置、Key、通过初筛候选人均存在才进入LLM，按规则分降序评估；不是全量人选先交给AI。来源：`bossmaster.py:5423-5432,5647-5667`。
- `_evaluate_single`→`_build_prompt`→`_call_llm_api`，由`ai_adapter.build_request`适配用户配置的base_url/model/key，再`requests.Session.post`调用。温度通常0.3，tool模式0；max_tokens1024。`submit_candidate_evaluation`为结构化输出schema，不是对BOSS的动作工具。来源：`llm_eval.py:65-126,455-464,658-724,933-943`，`constants.py:70-71`。

## 清洗与压缩

`build_llm_candidate_summary`默认4000字符。优先使用`_api_profile`结构化字段，无则重解析summary。统一空白、去空行、分段、标签去重，技能命中最多20、技能标签最多40；教育和工作经历最多各5条；API个人摘要600字符、教育700、工作800、职责1600、规则解释500。末尾截断标记`...`可能使结果略超4000。原候选人完整summary不因此覆盖，限制的是LLM入参。来源：`llm_eval.py:203-217,250-452`。

这不是完整匿名化或提示注入防御：摘要仍带姓名、性别等，不能把“清洗”理解为自动去敏。

## 硬条件与失败边界

- LLM verdict单独写fail不会直接淘汰。只有finding同时fail、high置信、证据是原summary子串，并符合代码支持的经验/统招学历/年龄/薪资/状态/城市规则，才进入淘汰。unknown只记录，初评函数不会仅因AI unknown自动置manual_review。来源：`llm_eval.py:593-655,1086-1103`。
- 确定性规则对一些缺失字段转人工，但普通required_conditions关键词未找到会直接拒绝；因此不能泛称“所有信息不足都会人工确认”。来源：`filtering.py:549-552,780-824`。
- 发现实现不一致：`candidate_scan_policy.py:64`生成`经验：要求≥N年`，而`llm_eval.py:604`匹配`经验：≥N年`。正常生成文本无法匹配该正则，可能使AI经验不足二次验证不生效；确定性经验初筛仍存在。这是静态发现，未运行验证。
- API失败/解析失败/异常时标记llm_error，不重新改分，不把失败本身当联系阻断条件。失败代码实际保留当时已有分数（重评时不一定是原始规则分），日志“保留原始分数”表述比实现更窄。来源：`llm_eval.py:1122-1151`，`bossmaster.py:5678-5681`。

## 示例（人工构造，非候选人数据）

技能权重命中8/10→40，最低3年实际5年→6，普通本科→3，优先项→4：规则分25+40+6+3+4=78。初评+8→86；若二次简历评估-5，则最终73，不是81。硬条件淘汰仍独立生效。
